네. 지금 조건이라면 **Java Worker가 데이터를 읽어서 파일로 만드는 방식이 아니라, AS-IS/TO-BE Sybase IQ 서버가 각각 직접 파일을 쓰고 읽도록** 구현하는 것이 맞습니다.

그리고 한 가지 중요한 사항을 먼저 정정하겠습니다.

**HP-UX AS-IS → Linux TO-BE라면 단순 `TEMP_EXTRACT_BINARY=ON`을 사용하면 안 됩니다.** SAP IQ 16.0 문서상 Binary Load는 endian-sensitive이고, 서로 다른 endian 플랫폼 간 이동에는 `TEMP_EXTRACT_BINARY=ON` + `TEMP_EXTRACT_SWAP=ON`인 **binary/swap extraction**을 사용하도록 되어 있습니다. SAP의 IQ 16.0 SP08 예제도 big-endian → little-endian 이동에서 `BYTE ORDER HIGH`를 사용하는 방법을 명시합니다. ([SAP 도움말 포털][1])

따라서 아래 프로그램은 **HP-UX → Linux 이관을 전제로 `BINARY/SWAP` 방식**으로 작성하겠습니다.

# 1. 최종 Worker 구조

이번 프로그램의 책임을 다음과 같이 제한하겠습니다.

```text
GODIS
  │
  │ tableName
  │ extractCondition
  │ jobId
  │ fileDirectory
  │ filePrefix
  │
  ▼
Shell
  │
  ▼
Java Worker
  │
  ├── AS-IS JDBC Connection
  │       │
  │       ├── SET TEMPORARY OPTION
  │       ├── SELECT
  │       └── 결과 확인
  │
  │
  └── TO-BE JDBC Connection
          │
          └── LOAD TABLE
                    │
                    ▼
              TO-BE IQ
```

실제 데이터 경로는:

```text
AS-IS IQ 16.0
     │
     │ SELECT
     ▼
IQ Extract Engine
     │
     │ 직접 WRITE
     ▼
50TB Shared Volume
     │
     │ 직접 READ
     ▼
IQ Load Engine
     │
     ▼
TO-BE IQ 16.2
```

입니다.

**Java에는 250TB 데이터가 전달되지 않습니다.**

SAP IQ의 extraction facility는 SELECT 결과를 직접 파일로 redirect할 수 있으며, `TEMP_EXTRACT_NAME1`이 지정된 경우 해당 파일을 IQ 서버가 생성합니다. ([SAP 도움말 포털][2])

# 2. 중요한 HP-UX → Linux endian 처리

이 프로젝트에서는 다음으로 설정합니다.

### AS-IS HP-UX

```sql
SET TEMPORARY OPTION TEMP_EXTRACT_BINARY = 'ON';
SET TEMPORARY OPTION TEMP_EXTRACT_SWAP = 'ON';
```

즉:

```text
Binary = ON
Swap   = ON
```

입니다.

SAP IQ 16.0 문서에서 extraction 종류를 다음처럼 정의합니다.

| BINARY | SWAP | 의미          |
| ------ | ---- | ----------- |
| OFF    | OFF  | ASCII       |
| ON     | OFF  | Binary      |
| ON     | ON   | Binary/Swap |

그리고 Binary/Swap은 **다른 endian 시스템으로 이동하기 위한 추출**입니다. ([InfoCenter][3])

따라서 현재 프로젝트에서는 이것이 핵심입니다.

# 7. SQL Utility

```java
package com.company.migration.util;

public final class SqlUtil {

    private SqlUtil() {
    }

    public static String escapeSqlLiteral(String strValue) {

        if (strValue == null) {
            return "";
        }

        return strValue.replace("'", "''");
    }

    public static String validateIdentifier(
            String strIdentifier) {

        if (strIdentifier == null
                || strIdentifier.trim().isEmpty()) {

            throw new IllegalArgumentException(
                "SQL identifier is empty.");
        }

        String strValue =
            strIdentifier.trim();

        /*
         * DBA.TABLE 형태를 허용한다.
         * 실제 프로젝트에서는 Metadata에서 검증된
         * table명만 전달하도록 하는 것을 권장한다.
         */
        if (!strValue.matches(
                "[A-Za-z_][A-Za-z0-9_]*" +
                "(\\.[A-Za-z_][A-Za-z0-9_]*)?")) {

            throw new IllegalArgumentException(
                "Invalid SQL identifier : "
                + strIdentifier);
        }

        return strValue;
    }
}
```

# 8. SybaseIQSqlBuilder.java

여기서 **Sybase IQ 문법을 직접 관리**합니다.

```java
package com.company.migration.sql;

import com.company.migration.util.SqlUtil;

public class SybaseIQSqlBuilder {

    public String buildExtractOptionSql(
            String strOutputFile,
            long lngExtractSizeKb) {

        String strSafeFile =
            SqlUtil.escapeSqlLiteral(strOutputFile);

        StringBuilder strBuilder =
            new StringBuilder();

        strBuilder.append(
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_NAME1 = '"
        );
        strBuilder.append(strSafeFile);
        strBuilder.append("'");

        return strBuilder.toString();
    }

    public String buildExtractBinarySql() {

        return
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_BINARY = 'ON'";
    }

    public String buildExtractSwapSql() {

        return
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_SWAP = 'ON'";
    }

    public String buildExtractName2ClearSql() {

        return
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_NAME2 = ''";
    }

    public String buildExtractSizeSql(
            long lngExtractSizeKb) {

        return
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_SIZE1 = " +
            lngExtractSizeKb;
    }

    public String buildExtractParallelDegreeSql(
            int intParallelDegree) {

        return
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_MAX_PARALLEL_DEGREE = " +
            intParallelDegree;
    }

    public String buildExtractSql(
            String strTableName,
            String strCondition) {

        String strSafeTableName =
            SqlUtil.validateIdentifier(
                strTableName);

        StringBuilder strBuilder =
            new StringBuilder();

        strBuilder.append(
            "SELECT * FROM "
        );

        strBuilder.append(
            strSafeTableName
        );

        if (strCondition != null
                && !strCondition.trim().isEmpty()) {

            strBuilder.append(" WHERE ");
            strBuilder.append(strCondition);
        }

        return strBuilder.toString();
    }

    public String buildExtractClearSql() {

        return
            "SET TEMPORARY OPTION " +
            "TEMP_EXTRACT_NAME1 = ''";
    }

    public String buildLoadSql(
            String strTargetTable,
            String strSourceFile,
            String strColumnList) {

        String strSafeTableName =
            SqlUtil.validateIdentifier(
                strTargetTable);

        String strSafeFile =
            SqlUtil.escapeSqlLiteral(
                strSourceFile);

        StringBuilder strBuilder =
            new StringBuilder();

        strBuilder.append(
            "LOAD TABLE "
        );

        strBuilder.append(
            strSafeTableName
        );

        strBuilder.append(" (");
        strBuilder.append(strColumnList);
        strBuilder.append(") ");

        strBuilder.append(
            "FROM '"
        );

        strBuilder.append(
            strSafeFile
        );

        strBuilder.append("' ");

        strBuilder.append(
            "FORMAT BINARY "
        );

        strBuilder.append(
            "STRIP OFF "
        );

        strBuilder.append(
            "QUOTES OFF "
        );

        strBuilder.append(
            "ESCAPES OFF "
        );

        /*
         * AS-IS HP-UX가 big-endian이고
         * TO-BE Linux가 little-endian인 경우
         */
        strBuilder.append(
            "BYTE ORDER HIGH"
        );

        return strBuilder.toString();
    }
}
```

# 9. 그런데 Load SQL의 핵심은 `BINARY WITH NULL BYTE`입니다

여기가 매우 중요합니다.

SAP IQ 16.0 문서의 Binary Extract 예제를 보면 각 컬럼을:

```sql
COLUMN_NAME BINARY WITH NULL BYTE
```

로 지정합니다.

그리고:

```sql
FORMAT BINARY
```

를 사용합니다. ([SAP 도움말 포털][1])

따라서 실제 Load SQL은:

```sql
LOAD TABLE DBA.CUSTOMER
(
    COL1 BINARY WITH NULL BYTE,
    COL2 BINARY WITH NULL BYTE,
    COL3 BINARY WITH NULL BYTE
)
FROM '/migration/CUSTOMER/customer.dat'
FORMAT BINARY
STRIP OFF
QUOTES OFF
ESCAPES OFF
BYTE ORDER HIGH;
```

형태가 되어야 합니다.

# 10. TO-BE에서 `BYTE ORDER HIGH`를 사용하는 이유

HP-UX AS-IS가 big-endian이고 Linux TO-BE가 little-endian이라면:

```text
AS-IS
HP-UX
BIG-ENDIAN
    │
    │ Binary/Swap
    ▼
Shared Volume
    │
    │
    ▼
TO-BE
Linux
LITTLE-ENDIAN
```

이 됩니다.

SAP IQ 16.0의 문서 예제에서도 big-endian source에서 생성한 binary file을 target에 Load하면서:

```sql
BYTE ORDER HIGH
```

를 지정합니다. ([SAP 도움말 포털][1])

따라서 **실제 HP-UX 하드웨어의 endian을 반드시 확인한 뒤 설정해야 합니다.**

HP-UX가 IA-64인지 PA-RISC인지 등 실제 플랫폼에 따라 검증이 필요합니다.

# 11. Unload Worker

```java
package com.company.migration.unload;

import com.company.migration.sql.SybaseIQSqlBuilder;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.Statement;

public class SybaseIQUnloadWorker {

    private final String strDbUrl;
    private final String strUser;
    private final String strPassword;

    private final SybaseIQSqlBuilder sqlBuilder;

    public SybaseIQUnloadWorker(
            String strDbUrl,
            String strUser,
            String strPassword) {

        this.strDbUrl = strDbUrl;
        this.strUser = strUser;
        this.strPassword = strPassword;

        this.sqlBuilder =
            new SybaseIQSqlBuilder();
    }

    public void execute(
            String strTableName,
            String strExtractCondition,
            String strOutputFile,
            long lngExtractSizeKb,
            int intParallelDegree)
            throws Exception {

        try (
            Connection conn =
                DriverManager.getConnection(
                    this.strDbUrl,
                    this.strUser,
                    this.strPassword);

            Statement stmt =
                conn.createStatement()
        ) {

            conn.setAutoCommit(true);

            configureExtract(
                stmt,
                strOutputFile,
                lngExtractSizeKb,
                intParallelDegree
            );

            String strExtractSql =
                sqlBuilder.buildExtractSql(
                    strTableName,
                    strExtractCondition
                );

            System.out.println(
                "[UNLOAD][START] "
                + strTableName
            );

            System.out.println(
                "[UNLOAD][SQL] "
                + strExtractSql
            );

            /*
             * 핵심:
             *
             * Java가 ResultSet을 읽지 않는다.
             *
             * SELECT 결과를 Sybase IQ Extract
             * Engine이 Shared Volume에 직접 기록한다.
             */
            stmt.execute(strExtractSql);

            System.out.println(
                "[UNLOAD][END] "
                + strTableName
            );

        } finally {

            /*
             * Connection close로 session 종료가 되지만
             * Extract Option을 명시적으로 해제하는 것을
             * 권장한다.
             *
             * 현재 구조에서는 finally에서 별도 Connection을
             * 열지 않고, 정상 실행 구간에서 clear하도록
             * 개선할 수 있다.
             */
        }
    }

    private void configureExtract(
            Statement stmt,
            String strOutputFile,
            long lngExtractSizeKb,
            int intParallelDegree)
            throws Exception {

        /*
         * 1. Output file
         */
        stmt.executeUpdate(
            sqlBuilder.buildExtractOptionSql(
                strOutputFile,
                lngExtractSizeKb
            )
        );

        /*
         * 2. Binary extraction
         */
        stmt.executeUpdate(
            sqlBuilder.buildExtractBinarySql()
        );

        /*
         * 3. Opposite-endian target용
         *    Binary/Swap
         */
        stmt.executeUpdate(
            sqlBuilder.buildExtractSwapSql()
        );

        /*
         * 4. NAME2 이후 파일 사용 방지
         */
        stmt.executeUpdate(
            sqlBuilder.buildExtractName2ClearSql()
        );

        /*
         * 5. 파일 크기
         *
         * TEMP_EXTRACT_SIZE는 KB
         */
        stmt.executeUpdate(
            sqlBuilder.buildExtractSizeSql(
                lngExtractSizeKb
            )
        );

        /*
         * 6. IQ Extract parallel degree
         *
         * 이 값은 GODIS Job 병렬도와 다른 개념이다.
         */
        stmt.executeUpdate(
            sqlBuilder.buildExtractParallelDegreeSql(
                intParallelDegree
            )
        );
    }
}
```

# 12. 여기서 중요한 점: `TEMP_EXTRACT_MAX_PARALLEL_DEGREE`

이것은 제가 앞서 설명했던:

```text
GODIS에서 동시에 실행하는 Java Worker 수
```

와 완전히 다른 것입니다.

예를 들어:

```text
GODIS
 ├─ Worker A
 ├─ Worker B
 └─ Worker C
```

와

```text
Worker A
   ↓
IQ Extract
   ↓
TEMP_EXTRACT_MAX_PARALLEL_DEGREE = 8
```

은 서로 다른 병렬성입니다.

SAP IQ의 Extract Option에는 `TEMP_EXTRACT_MAX_PARALLEL_DEGREE`가 있으며 16.x 문서상 허용 범위는 2~64입니다. ([SAP 도움말 포털][2])

따라서 실제 튜닝에서는:

```text
GODIS Job Concurrency
×
IQ Extract Parallel Degree
×
TO-BE Load Parallelism
```

을 같이 봐야 합니다.

**무조건 크게 설정하면 안 됩니다.**

# 13. Load Worker

```java
package com.company.migration.load;

import com.company.migration.sql.SybaseIQSqlBuilder;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.Statement;

public class SybaseIQLoadWorker {

    private final String strDbUrl;
    private final String strUser;
    private final String strPassword;

    private final SybaseIQSqlBuilder sqlBuilder;

    public SybaseIQLoadWorker(
            String strDbUrl,
            String strUser,
            String strPassword) {

        this.strDbUrl = strDbUrl;
        this.strUser = strUser;
        this.strPassword = strPassword;

        this.sqlBuilder =
            new SybaseIQSqlBuilder();
    }

    public void execute(
            String strTargetTable,
            String strSourceFile,
            String strColumnList)
            throws Exception {

        String strLoadSql =
            sqlBuilder.buildLoadSql(
                strTargetTable,
                strSourceFile,
                strColumnList
            );

        try (
            Connection conn =
                DriverManager.getConnection(
                    this.strDbUrl,
                    this.strUser,
                    this.strPassword);

            Statement stmt =
                conn.createStatement()
        ) {

            conn.setAutoCommit(true);

            System.out.println(
                "[LOAD][START] "
                + strTargetTable
            );

            System.out.println(
                "[LOAD][SQL] "
                + strLoadSql
            );

            /*
             * Java가 Shared Volume의 파일을
             * 읽는 것이 아니다.
             *
             * TO-BE IQ Server가 파일을 직접 읽는다.
             */
            stmt.execute(strLoadSql);

            System.out.println(
                "[LOAD][END] "
                + strTargetTable
            );
        }
    }
}
```

SAP IQ의 `LOAD TABLE`은 파일의 대량 데이터를 기존 IQ 테이블에 효율적으로 적재하는 Bulk Load 기능입니다. Load가 성공하면 자동 savepoint가 해제되고, 실패 시에는 해당 동작을 오류 처리할 수 있습니다. ([SAP 도움말 포털][4])

```java
public String buildBinaryColumnList(

    StringBuilder strBuilder =
        new StringBuilder();

    for (int intIndex = 0;
         intIndex < listColumnName.size();
         intIndex++) {

        if (intIndex > 0) {
            strBuilder.append(", ");
        }

        strBuilder.append(
            SqlUtil.validateIdentifier(
                listColumnName.get(intIndex))
        );

        strBuilder.append(
            " BINARY WITH NULL BYTE"
        );
    }

    return strBuilder.toString();
}
```

# 18. `TEMP_EXTRACT_SIZE1`은 20GB로 설정

앞서 말씀드렸던 것처럼 이 값은 **KB**입니다.

SAP IQ 문서도 `TEMP_EXTRACT_SIZE<n>`의 단위를 KB로 명시합니다. ([SAP 도움말 포털][2])

따라서:

```java
long lngExtractSizeKb =
    20L * 1024L * 1024L;
```

입니다.

결과:

```text
20,971,520 KB
```

입니다.

그리고 이것은 **Java가 20GB씩 파일을 만드는 것이 아니라 IQ Extract Engine이 파일 크기 기준으로 분할하는 것**입니다.

SAP IQ는 `TEMP_EXTRACT_SIZE<n>`에 도달하면 `TEMP_EXTRACT_FILE_PREFIX`/thread/filecount 규칙을 이용해 extract 파일을 생성할 수 있습니다. ([SAP 도움말 포털][5])

# 21. 그런데 LOAD 쪽에서는 여러 파일을 어떻게 처리할 것인가?

이 부분도 중요합니다.

IQ `LOAD TABLE`은 여러 input file을 지정할 수 있습니다. 따라서:

```sql
LOAD TABLE DBA.CUSTOMER
(
    ID        BINARY WITH NULL BYTE,
    NAME      BINARY WITH NULL BYTE,
    REG_DATE  BINARY WITH NULL BYTE
)
FROM
    '/migration/JOB001/TABLE_A/TABLE_A_1_1.dat',
    '/migration/JOB001/TABLE_A/TABLE_A_2_1.dat',
    '/migration/JOB001/TABLE_A/TABLE_A_3_1.dat'
FORMAT BINARY
...
```

형태로 구성할 수 있습니다.

SAP IQ의 `LOAD TABLE`은 ASCII와 binary 모두 지원하며, 대량 데이터를 효율적으로 적재하기 위한 Bulk Load 명령입니다. ([SAP 도움말 포털][6])

따라서 실제 Worker에서는 **"파일 하나 = Java Worker 하나"**로 만들기보다:

```text
Migration Job
    │
    ├── Extract files
    │    ├── 001
    │    ├── 002
    │    ├── 003
    │    └── ...
    │
    └── LOAD TABLE
         FROM file001,file002,file003...
```

구조가 더 좋습니다.

# 24. 특히 이번 프로젝트에서는 ASCII보다 Binary/Swap을 우선 검토할 가치가 있습니다

SAP IQ 16.0 문서상 Binary Extract는 대량 결과 추출에 성능상 장점이 있으며, Binary Load는 fixed-width 방식이어서 delimiter 기반 처리보다 효율적일 수 있습니다. ([SAP 도움말 포털][1])

하지만 이번 환경은:

```text
HP-UX
   ↓
Linux
```

이므로 단순 Binary가 아니라:

```text
TEMP_EXTRACT_BINARY = ON
TEMP_EXTRACT_SWAP   = ON
```

을 사용해야 합니다.

즉:

```text
추천
★★★★★
Binary/Swap

Fallback
★★★☆☆
ASCII
```

로 PoC를 진행하는 것이 좋습니다.

## 핵심 결론

이번 조건에서는 **Java Worker를 "데이터 이관 프로그램"으로 만들면 안 되고 "Sybase IQ 명령 실행 Worker"로 만드는 것이 핵심**입니다.

특히 다음 원칙을 지키는 것을 권장합니다.

1. **Java는 ResultSet을 읽지 않는다.**
2. **Java는 파일을 생성하지 않는다.**
3. **AS-IS IQ가 Shared Volume에 직접 Extract한다.**
4. **TO-BE IQ가 Shared Volume에서 직접 Load한다.**
5. `TEMP_EXTRACT_BINARY=ON`을 사용하되 **HP-UX → Linux endian 차이를 고려하여 `TEMP_EXTRACT_SWAP=ON`을 검토한다.**
6. Binary Load 시 **모든 컬럼에 `BINARY WITH NULL BYTE`를 적용한다.** ([SAP 도움말 포털][1])
7. TO-BE Load에는 source가 big-endian인 경우 **`BYTE ORDER HIGH`**를 적용한다. ([SAP 도움말 포털][1])
8. `TEMP_EXTRACT_SIZE<n>`은 **KB 단위**다. ([SAP 도움말 포털][2])
9. GODIS가 Batch 병렬성을 관리하므로 Java Worker 내부의 `ExecutorService`는 제거한다.
10. `TEMP_EXTRACT_MAX_PARALLEL_DEGREE`는 **GODIS의 Job 병렬도와 별개의 IQ 내부 병렬도**이므로 PoC로 최적값을 찾아야 한다.
11. LONG BINARY/LONG VARCHAR는 일반 BINARY와 별도의 `BINARY FILE(...)`/`ASCII FILE(...)` Load 전략이 필요하다. ([SAP 도움말 포털][7])

그리고 **가장 먼저 해야 할 것은 실제 HP-UX IQ 16.0의 SP/ESD 레벨과 CPU/파일시스템 endian을 확인하고 1개 테스트 테이블로 Binary/Swap → Linux IQ 16.2 Load를 검증하는 것**입니다. SAP의 IQ 16.0 문서 자체가 서로 다른 endian 시스템 간 Binary 이동 절차를 별도로 설명하고 있기 때문에, 250TB 전체 이관 전에 이 PoC를 통과시키는 것이 필수적입니다. ([SAP 도움말 포털][1])

**다음 구현 단계에서는 위 코드를 실제 운영형으로 확장할 때 `TableMetadata/ColumnMetadata → BINARY WITH NULL BYTE 자동 생성 → 여러 Extract 파일을 하나의 LOAD TABLE에 연결 → LONG BINARY/LONG VARCHAR 처리 → 파일 Manifest → Row Count/SUM/MIN/MAX 검증 → GODIS Exit Code`까지 하나의 Worker로 묶는 것이 좋습니다.**
